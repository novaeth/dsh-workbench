# 语域：成熟产品的文案标准

读者不同，语域不同；同一个词，在界面、agent 交代与技术细节里必须同名。
先判读者，再定语域，最后查词表。

## 一句话

像成熟软件，不像同事聊天，也不像内部文档。
通俗不等于口语：用户能读懂，同时每个词都经得起产品说明书的标准。

## 六条

1. **标准书面语。** 不用语气词（吧 / 呢 / 啊 / 嘛）、网络语（搞定 / 收工 / 上板）、拟人（起不来 / 活了 / 挂了）、比喻（地板 / 两条腿 / 一把）。
2. **一个概念一个词。** 界面、文档、agent 交代、工具面用同一个词；同义词只留一个。
3. **动词精确。** 安装 / 卸载 / 更新 / 启动 / 重启 / 运行 / 停止 / 打开 / 查看 / 复制 / 重试 / 保存 / 删除 / 添加 / 移除 / 启用 / 停用 / 批准 / 允许 / 取消。
4. **状态固定。** 未安装 / 已安装 / 可更新 / 更新中 / 更新失败 / 运行中 / 已完成 / 待查看 / 等待批准 / 已暂停 / 不可用。
5. **句子克制。** 陈述句为主；指令句用「请 + 动词」；按钮用动词原形；不用感叹号；一句话一个动作；界面句尽量不超过 25 字。
6. **信息完整。** 发生了什么 + 原因 + 下一步；不写「操作成功」「已完成」这种没有对象和结果的句子。

## 先写句，再查词

词表是底线，不是写法。先按意思把整句写出来，再查词表；不要逐词替换。

机械替换的五个信号：

1. 一句话里两个冒号，或靠「——」拼接两件事。
2. 主语消失，只剩「该 / 此 / 其 / 这份」。
3. 「请」堆叠，或一句话塞三个动作。
4. 术语都对了，但读起来像翻译。
5. 信息顺序反了：原因在前、结论在后。

命中任一条，整句重写，不是换词。

## 三档语域

| 语域 | 用在哪 | 写法 |
|---|---|---|
| 界面 | 按钮、状态、空态、阻断、错误、审批、配置 | 标准书面语；短句；固定词表；不出现内部词 |
| 交代 | agent 回复、引导、解释 | 专业但可读；结论 + 位置 + 下一步；不寒暄、不卖萌、不写内部黑话 |
| 技术 | 高级设置页、detail、日志、CLI | 术语可用，但首次出现给界面词；原文原样、可检索 |

## 不写什么

- **内部词**：profile / adapter / schema / payload / bundle / patch / stderr / probe / unit / daemon / opencli / 索引源 / 适配器集合 / 体检 / 模块 id / 产物目录 / 上下文。
- **口语词**：在跑 / 跑完 / 起不来 / 装上 / 卸掉 / 换上 / 这一下 / 这一跳 / 点进去 / 点头 / 上板 / 收工 / 弄 / 搞 / 造 / 就好 / 就行。
- **套近乎**：帮你 / 替你 / 给你 / 不用你点 / 咱们 / 我们。
- **空话**：操作成功 / 已完成（没有对象）/ 请稍后重试（没有原因或下一步）。

例外只有两类：日志与 CLI 里的技术词（要与界面词同源、可 grep）；高级设置页首次出现的术语（必须给界面词或一句解释）。

## 改写五问

1. 这句话里的名词，用户在界面上找得到吗？
2. 动词是词表里的标准词吗？
3. 状态是固定状态词吗？
4. 用户读完知道下一步做什么吗？
5. 把技术细节拿掉，这句话还成立吗？

## 例

| 现在 | 改成 |
|---|---|
| 长任务在跑 | 长任务运行中 |
| 造一个模块 | 创建模块 |
| ⚠ 起不来 | ⚠ 启动失败 |
| 还没换上：可能网慢或没装上。再点一次「更新」；一直这样就把 dsh 重启一遍。 | 更新还没有生效。可能是网络较慢或安装未完成，请重试；如果仍然失败，请重启 dsh。 |
| 这一段录完了 —— agent 会自己来取并收工，不用你点 | 录制已完成。agent 会自动读取结果，无需操作。 |
| 这一下动到了 dsh 自己加载的模块 | 本次操作修改了 dsh 自身加载的模块。 |
