# FOR-AGENT：给 agent 的文本

读者是模型。它在注册时读描述，调用时读返回，中途读通知，审批前读 `reason` / `{blocked}`。

## 一条规则

**agent 自己能推出来的，就不写。**

工具名、参数名、schema（`enum` / `type` / `required`）、上一次调用的输出，这四样已经说了的，不再说第二遍。
完整清单与理由：`prompt-diet/spec.md`。

删：字段清单、枚举释义、参数名复述、输出里已有的话、理由与复述、“谁读它”的注解、路线图。
留：写与危险、跨工具下一步与字面量、机器码 ↔ 人话、非显然的默认与上限、会误导的坑、安全事实。

## 各面

### `description`

- 一句“是什么” + 一句“什么时候用”。
- 动作用动词；名字已经说了的不重复。
- 用户会说的触发词可以留（帮助模型认场景），但不要解释产品结构。
- 不写“这个工具用于……”这种空开头。

### 参数 `description`

- 只写：默认、上限、取值范围、格式、坑。
- 枚举含义不写（`enum` 自明）；参数名不复述。
- 字段名用模型能懂的名字，不用平台内部名。
- dsh 认的 schema 关键字有限；多一个会被判 `UNSUPPORTED_SCHEMA`（见 `tool-surface.test.ts`）。

### 返回

- 事实 + 总数 / 分页 + 下一次调用。
- ID、版本、单位、时间戳原样；不翻译、不概括、不四舍五入。
- 可被引用：agent 可能把它贴给用户，所以不写只有界面才懂的缩写。
- 截断说清截了什么、完整版在哪。
- 不写“操作成功”“已完成”这种没有事实的句子。

### 错误 / `reason` / `{blocked}`

- 发生了什么 + 能不能重试 + 下一步。
- `reason` / `{blocked}` 是给模型的，不是给界面的：一句话，不用界面语气，不用“请”。
- 不甩堆栈；给稳定的 code 和一条修法。
- 拒绝理由必须让模型知道“改成什么才能继续”。

### 中断通知

- 自包含：谁做了什么 + 哪件事变了 + 现在做什么。
- 一两句；不引用“上面”或“刚才那一步”。
- 例：调试被暂停 → “现在别再把那一屏当目标；在那之前照常改源码 / build / 跑门禁。”

### `context.render`

- 一行；点名对象；不出现内部 id 之外的修饰。
- 输出的文字会进模型上下文，按“下一件事”写。

## 预算

- 常驻工具面有总字数棘轮：跑 `tool-surface.test.ts` 拿预算。
- 加描述先减描述；新工具先算字数。
- 预算是整面的，不是每把工具的上限。

## 验收

1. 注册后打印每把的 `description` + 参数说明，逐句问“模型推得出来吗”。
2. 真调一次，读原始返回：有事实、有下一步、值原样。
3. 漏参数 / 错参数各一次，读报错：能照做。
4. 跑 `tool-surface.test.ts`。

## 例

| 面 | 改前 | 改后 |
|---|---|---|
| 描述 | 这个工具用于查看面板状态 | 面板此刻的真实样子（每张卡读到没 / 崩没崩）；用户说卡片不对就先调它 |
| 参数 | `unit=单元编号` | `unit`：单元 id；不填 = 全部 |
| 返回 | 操作成功 | 已安装 `[inventory]`；下一步 `workbench_diy_show unit=inventory` |
| 拒绝 | 不允许 | 已经有一场录制活着；先 `_record_stop` |
| 通知 | 调试状态变了 | 用户按了「暂停」：这场调试暂停了；现在别再看那一屏 |
