# FOR-USER：给终端用户的文本

读者不写代码，可能在赶时间，也可能第一次打开这块面板。

## 通俗四条

1. **可复述**：把这句话给一个不写代码的人，他能说出下一步做什么。答不出就重写。
2. **名词看得见**：每个名词都是产品里看得见的东西（项目、卡片、构建、环境），不是内部概念。
3. **一句一个意思**：不靠括号补解释，不写“即……”，一句里不放两个动作。
4. **遮住原文**：只读主句，用户知道发生了什么、下一步做什么；技术细节在原文里。

## 面与预算

| 面 | 预算 | 必须带 |
|---|---|---|
| 卡片标题 | ≤12 汉字 | 和卡内容一致的名词短语 |
| 空态 | 1 句 + 可选 hint | “没有什么” + 怎么才有 |
| 加载 | ≤8 字 | 不解释、不道歉 |
| 阻断 | 标题 1 句 + hint 1 句 + 1 动作 | 缺什么 / 为什么 / 去哪 |
| 行内提示 | ≤20 字 | 一条事实 |
| 按钮 | 动词 + 对象，≤6 字 | 点了会发生什么（“发布到生产”） |
| 配置 | 标签 ≤8，说明 ≤30 | 默认 + 影响 |
| 审批问句 | ≤40 字；装配 ≤108 | 对象 + 动作 + “允许吗” |
| 审批明细 | ≤20 字 / 行 | 一行一个事实 |
| agent 交代 | ≤2 句 | 结论 + 位置 + 下一步 |
| 启动体检 | 主句 1 句 + 原文 | 哪一步没过 + 点哪 |
| 市场 / 重启状态 | 状态词 + 原因 + 动作 | 现在怎样 + 为什么 + 能做什么 |
| 调试 / 录制底栏 | 状态 + 一颗键 | 现在在做什么 |
| a11y / placeholder | 动作 + 对象 | 不带“按钮 / 输入框”这类角色词 |

审批那三个数字来自 ADR-0065；其余是**本 skill 口径**，可调。
审批文案的动作与目标写法照 `approval-copy/spec.md`。

## 词表

不是词典，是判据：**用户会管它叫什么？** 查不到就换词或删掉。

| 内部 | 主句里的说法 |
|---|---|
| unit / 单元 | 这个模块 / 这张卡（用界面上的词） |
| 套件 | 面板 / 模块 |
| 宿主 | 工作台后台 |
| 投影 / 事实 | 数据 |
| runtime / daemon | 后台服务 |
| opencli | 按用户能做的事说：浏览器连接 / 后台服务 |
| schema / payload / bundle / patch / profile / stderr | 不出现；进原文 |
| probe / adapter | 不出现；进原文 |

状态词只有四义：**在做 / 做完了 / 出错 / 没在跑**。
时间写相对时间（“2 分钟前”“昨天”），不写原始时间戳；单位跟在数字旁（“3 条”）。
读不到不显示 0。

## 两层

主句 + 原文成对：

- 主句给人，不含错误码、路径、堆栈、内部词。
- 原文进 `detail` / 折叠区 / 日志，原样保留。

判据：

1. 遮住原文只读主句：知道发生了什么、下一步做什么。
2. 遮住主句只读原文：开发能定位。

安装命令是特例：主句说“装什么、为什么”，下一行原样命令；命令不翻译、不拆成散文。

## zh / en

- 两语都写；键带 `<unit>.`；两种语言同构。
- 英文重写，不直译；长度 ≤ 中文 ×3。
- 中文全角标点，英文 sentence case；不用感叹号。
- 同一条规则管两语，不因为英文就放宽。

## 验收

1. 真卡片五种状态各看一遍；两语各看一遍。
2. 逐句过“可复述”和“名词看得见”。
3. 遮住原文只读主句，走一遍主流程。
4. 审批屏对黄金屏；模块跑 `check --only cards`。

## 例

| 改前 | 改后 |
|---|---|
| 暂无数据 | 这个环境还没有构建记录。换一个环境，或先跑一次构建。 |
| 系统内部错误，请稍后重试 | 这次没读到发布记录。检查网络后重试。 |
| 操作成功 | 已发布到生产（v1.2.3）。 |
| 确定 / 取消 | 发布到生产 / 取消 |
| 去登录 | 去 GitHub 登录 |
| opencli 的隔离运行时还没装好 | 后台工具还没准备好。检查后台服务后重试。 |
| The data is empty | No builds in this environment yet. |
