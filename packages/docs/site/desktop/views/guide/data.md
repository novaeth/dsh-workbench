# 数据与设置

一句话：**会话、项目、附件三种装法共用一份；设置与插件各一份。**

| 装法 | 会话 / 项目 / 附件 | 设置 | 登录凭据 |
| --- | --- | --- | --- |
| 独立实例 | 跟 web 同一份（`~/.dsh`） | 自己一份（`:3081` 的 Settings） | 与 web 共用 |
| 装进 `dsh web` | 沿用当前 | 用 `dsh web` 的设置 | 同一份 |
| Desktop | 沿用 Desktop 的 | 用 Desktop 的设置 | 同一份 |

## 设置在哪

- 独立实例：`:3081` 的 **Settings**。想少配一遍，可以从 `dsh web` 同步已经配好的行：
  设置 → 工作台设置 → 配置同步 → 选来源 → 勾行 → 同步。
- 装进 `dsh web` / Desktop：就在各自原来的设置里，工作台不多一个入口。

## 端口与实例

```bash
WORKBENCH_PORT=3091 npx @dsh-workbench/core
npx @dsh-workbench/core --profile wb2
```

`--profile` 决定使用哪套**设置与运行时**（opencli、工坊、模块市场各一份）。会话和项目是共用的，
因此两个实例可以同时运行；只是不要在两边同时打开同一个会话，dsh 会给它加跨进程写锁，另一边无法打开。
项目列表按整份文件写入：两边同时修改项目时，以最后写入的那份为准；重要改动完成后，重启另一边再操作。

## 备份与清理

- 会话、项目、附件：位于 `~/.dsh/{sessions,storages,attachments}`，与 `dsh web` 共用。需要备份时，复制这三个目录即可。
- 工作台运行时（opencli、工坊、模块市场、自更新日志）：`~/.dsh/workbench`；其他 profile 在 `~/.dsh/<名字>`。
- 恢复原样：移除插件、停止实例，再删除 `~/.dsh/profiles/workbench` 与 `~/.dsh/workbench`。它不会影响你的项目文件，也不会删除共用的会话与项目。
- 浏览器里的 OpenCLI 扩展和平台登录状态不在这几个目录里：删除工作台不会移除它们；不再使用时，请到扩展页移除。

:::tip 从旧版本升级上来的实例
旧版本把会话 / 项目 / 附件也按 profile 分开存放。新版**不会**自动合并；请先退出所有 dsh，再执行：

```bash
dsh-workbench migrate          # 切共用根 + 并旧会话/项目/附件
dsh-workbench migrate --force  # 已经迁过一次、想再补并一次
```

迁移只补充缺少的部分，不覆盖已有内容，旧目录会保留。启动时如果看到 `dsh-workbench migrate` 提示，说明还有旧数据没有迁移。
更新后，也可以直接在模块市场的「工作台」那一行点「迁移旧数据」，它和命令行使用同一套逻辑。
这只是一条提示：点「不再提醒」只会收起提示，不会删除旧数据；旧项目仍在旧目录，以后仍然可以执行 `dsh-workbench migrate`。
:::

:::tip 登录凭据是共用的
共用的是「你已经登录过这个平台」这个状态，而不是会话内容；会话现在也是同一份。
:::

## 更换机器

在新机器上安装一遍、登录一次即可；会话和项目位于 `~/.dsh/{sessions,storages,attachments}`。
模块通过安装获得，重新安装一次比复制目录更可靠。
