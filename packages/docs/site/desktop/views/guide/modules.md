# 面板与模块

右侧那块面板的能力不是内置的，是**模块**。工作台本身不带业务模块 —— 装什么有什么。

## 模块是什么

一个独立的小包，声明自己占哪张卡、调哪些工具、读哪份状态。装上之后右侧多一张卡片，
卸掉就没了。它可以是别人发布的，也可以是 agent 当场给你做的。

## 面板的数据从哪来

面板不自己存数据：读的是你浏览器里的登录状态，经 OpenCLI 浏览器扩展交给本机的 opencli 运行时。
所以第一次要凑齐三件事：

- 浏览器里装好并启用了 **OpenCLI 扩展**（见 <PagodaDocLinkToView view="guide/quickstart">快速开始</PagodaDocLinkToView>）
- 浏览器开着，「准备工作台」里「浏览器连接」是已连接
- 要看的平台登录过（卡片上会提示，登录一次就够）

少一件，要靠登录状态的卡片就会空着或停在加载态；「准备工作台」会指出是哪一件。

## 装 / 升 / 卸

「工作台模块市场」分两个面：

- **已安装**：装、升、卸都在这里。也可以「添加模块」直接填包名、git 地址或本地目录；
  模块要的共用依赖和 opencli 插件在这一页各自成段，工作台自己的更新与旧数据迁移也在这里。
- **发现**：从索引源浏览模块，按版本装。第一次用要先加一个索引源（http 地址或 git 仓库）；
  索引源是同事或团队维护的目录，不是官方签名，装之前会让你确认来源。

多数模块装完即时生效；需要重启工作台才能生效的，结果里会说明原因。要跑安装脚本的包会先问你。
不方便点的时候，直接说：

> 帮我装一下缺陷面板

agent 会走工具装、启用、刷新，失败会说明卡在哪一步。

## DIY：让 agent 现场做一个

不想找现成的、或者要的面板市面上没有，就开 DIY 模式。agent 会在工作区里建骨架、
写代码、跑判据、装上去。你不用先学一套框架；写得对不对由门禁兜。

骨架、判据、模板都在仓库的 `packages/module-tools`，模块 DIY 的共用口径只有一份，
住在 `packages/core/skills/workbench-module-diy/`，不在文档里另抄。

做好之后还能发布：把 git 索引源设为「可发布」（仓库写权限归它的所有者），再跟 agent 说
「发布这个模块」；发布前会弹一次审批。这一版改了什么会记进更新日志，随包发出去；
一个包名归第一次发布的人，换署名发同名会被拒。

## 一条硬规矩

:::warning 看板承载轻交互，写入走动作路由或 agent 工具
筛选、展开、复制，以及用户直接发起的单步动作（如发布），都可以留在看板上。单步动作必须与一把
agent 工具共用同一实现，并记一次 run；批量、跨对象、需要编排的写入，仍交给 agent 工具与审批。
:::

模块清单里标了 `writes` 的工具必须给出审批口径（`needsApproval`），没有就当场判红 ——
agent 侧的写入只能走这条路。

## 面板长什么样的

- 一张卡片一个视角：缺陷、构建、分析，各自一列
- 空态、加载、失败都有话说，不留白屏
- 需要登录的平台按卡片提示登录，回来点「重试」

装不出卡片、一直转圈，先看 <PagodaDocLinkToView view="faq">常见问题</PagodaDocLinkToView>。
