# 面板与模块

右侧面板的能力不是内置的，全部来自**模块**。工作台本身不附带业务模块，安装什么就有什么。

## 模块是什么

一个独立的小包，声明自己占哪张卡、调用哪些工具、读取哪份状态。安装之后右侧会多一张卡片，
卸载后卡片随之消失。它可以是别人发布的，也可以是 agent 当场为你创建的。

## 面板的数据从哪来

面板不自己存数据。它读取你浏览器里的登录状态，经 OpenCLI 浏览器扩展交给本机的 opencli 运行时。
因此第一次使用需要凑齐三件事：

- 浏览器里安装并启用了 **OpenCLI 扩展**（见 <PagodaDocLinkToView view="guide/quickstart">快速开始</PagodaDocLinkToView>）
- 浏览器开着，「准备工作台」里「连接浏览器」那一行是已连接
- 要看的平台登录过（卡片上会提示，登录一次就够）

少一件，要靠登录状态的卡片就会空着或停在加载态；「准备工作台」会指出是哪一件。

## 装 / 升 / 卸

「工作台模块市场」分两个面：

- **已安装**：安装、升级、卸载都在这里。也可以「添加模块」直接填写包名、git 地址或本地目录；
  模块要的共用依赖和 opencli 插件在这一页各自成段，工作台自己的更新与旧数据迁移也在这里。
- **发现**：从模块来源浏览可用模块，按版本安装。第一次使用需要先添加一个模块来源（http 地址或 git 仓库）。
  模块来源由同事或团队维护，并非官方签名，安装前会让你确认来源。

点击已安装的模块、插件或工作台那一行，可以打开详情页：包名、安装源、版本都有记录；
有新版本时，还会说明新版来自哪里。

多数模块安装后立即生效；需要重启工作台才能生效的，结果里会说明原因。需要运行安装脚本的包会先询问你。
不方便点击时，直接说：

> 帮我装一下缺陷面板

agent 会通过工具安装、启用并刷新；如果失败，会说明停在哪一步。

## DIY：让 agent 现场做一个

找不到现成的模块，或者想要的面板市面上没有，就开启 DIY 模式。agent 会在工作区里创建骨架、
编写代码、运行判据并安装。你不需要先学一套框架；写得对不对由门禁把关。

骨架、判据、模板都在仓库的 `packages/module-tools`，模块 DIY 的共用口径只有一份，
住在 `packages/core/skills/workbench-module-diy/`，不在文档里另抄。

创建完成后还可以发布：把 git 模块来源设为「可发布」（仓库写权限归它的所有者），再告诉 agent
「发布这个模块」；发布前会有一次审批。这一版的改动会记进更新日志，随包发出去；
一个包名归第一次发布的人所有，更换署名发布同名包会被拒绝。

## 一条硬规矩

:::warning 看板承载轻交互，写入走动作路由或 agent 工具
筛选、展开、复制，以及用户直接发起的单步动作（如发布），都可以留在看板上。单步动作必须与一把
agent 工具共用同一实现，并记一次 run；批量、跨对象、需要编排的写入，仍交给 agent 工具与审批。
:::

模块清单里标了 `writes` 的工具必须给出审批口径（`needsApproval`），没有就当场判红 ——
agent 侧的写入只能走这条路。

## 面板长什么样

- 一张卡片一个视角：缺陷、构建、分析，各自一列
- 空态、加载、失败都有说明，不留白屏
- 需要登录的平台按卡片提示登录，回来点「重试」

如果卡片始终无法显示或一直在加载，请先查看 <PagodaDocLinkToView view="faq">常见问题</PagodaDocLinkToView>。
