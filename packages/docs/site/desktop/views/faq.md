# 常见问题

## 启动失败

| 症状 | 怎么办 |
| --- | --- |
| 启动被拒，说 dsh 太旧 | `npm i -g @deepseek-ai/dsh@latest`，再重启工作台 |
| `:3081` 端口被占用 | 执行 `WORKBENCH_PORT=3091 npx @dsh-workbench/core`（直接 `dsh workbench` 时同一个变量同样生效） |
| 启动正常但页面没有反应 | 换用现代浏览器；检查终端输出；插件冲突也会导致这一现象 |

## 浏览器连接

| 症状 | 怎么办 |
| --- | --- |
| 「准备工作台」里「连接浏览器 · 还没连上」 | 多半是扩展未安装或未启用。请从 [Chrome 应用商店安装 OpenCLI](https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk)，在扩展页确认已启用，保持浏览器打开，再回到这一屏点「重试」 |
| 点「打开浏览器」没有反应 | 这个按钮只在 Desktop 里出现；它会打开上次承载扩展的那个浏览器（没记住就用 Chrome）。如果打开后仍然连不上，请检查扩展是否被禁用 |
| 提示连接了多个浏览器账号 | 每个浏览器账号各有一个扩展实例，工作台不会自行猜测。请按页面上给出的命令列出账号，并选择一个默认账号 |
| 面板一直空白 / 持续加载 | 请依次确认：这个工作区已安装模块、要查看的平台已登录、「准备工作台」里「连接浏览器」那一行显示已连接；第一次加载可能需要几秒 |

## 界面不对

| 症状 | 怎么办 |
| --- | --- |
| 左栏恢复出厂、右侧面板消失 | 插件被关闭了。打开 Settings → 插件，重新启用 `@dsh-workbench/core`；如果进不去，按 `Meta+,` |
| 左栏没有「工作台DIY」、模式里也没有「工作台 DIY 模式」 | 多半是 dsh 版本太旧：DIY 模式在启动时从本次 dsh 的 `standard` 派生，旧版本没有注册入口就无法派生，而且不会报错。「准备工作台」会指出这一点并给出升级命令，升级 dsh 后重启即可 |
| 打开面板 / 按刷新要等 5–8 秒 | 正常现象：opencli 每次调用都有固定开销，数据一律实时读取、不使用缓存 |
| 页面白屏 / 提示插件加载失败 | 多半是插件冲突。请重启工作台并检查插件开关；仍未解决就到仓库提交 issue |

## 装进 Desktop 之后

- **没有变化**：确认安装的是 Desktop 那份 profile，而不是另建的实例；安装完成后需要重新打开窗口。
- **提示需要重启 / 权限**：退出并重新打开 Desktop，再试一次。
- **浏览器一直未连接**：浏览器没有打开，或扩展未安装 / 被禁用；这一屏有「打开浏览器」，打开后会自动复检。
- **`:3081` 上运行的是另一个实例**：那是独立实例，有自己的设置与运行时；会话和项目跟 Desktop 是同一份。Desktop 不需要运行 `setup`。

## 数据对不上

- 会话、项目、附件三种装法**共用一份**（在 `~/.dsh` 下）；设置与插件各一份。
- 换了 `--profile` 换的是设置与运行时（opencli、工坊、模块市场），不是会话和项目。
- 从旧版本升级上来的实例，旧会话不会自动迁移；请先退出所有 dsh，再执行 `dsh-workbench migrate`（只补充缺少内容，不覆盖，旧目录保留）。
- 两边同时打开同一个会话时，dsh 的写锁只允许一边打开，在另一边换一个会话即可。
