# 常见问题

## 启动失败

| 症状 | 怎么办 |
| --- | --- |
| 启动被拒，提示 dsh 太旧 | 升级 Desktop，再重启；仍被拒时先在模块市场更新工作台 |
| 启动正常但页面没有反应 | 重启 Desktop；仍有问题请检查插件开关与终端输出 |

## 浏览器连接

| 症状 | 怎么办 |
| --- | --- |
| 「准备工作台」里「连接浏览器 · 还没连上」 | 先在 `chrome://extensions` 里确认有没有 OpenCLI、开关是否打开：已安装的话回到这一屏点击「重试」；未安装的话，从 [Chrome 应用商店安装 OpenCLI](https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk)，或离线加载工作台自带的那份 —— 打开 `chrome://extensions`、开启「开发者模式」、点击「加载已解压的扩展程序」，选择启动检查里显示的目录（默认 `~/.dsh/workbench/opencli/extension`）。安装完成后确认已启用、保持浏览器打开，再回到这一屏选择「重试」 |
| 更新工作台后需要重新选择扩展目录吗 | 不需要。自带的副本在固定路径（默认 `~/.dsh/workbench/opencli/extension`），更新只替换其中的文件；扩展自身升级时，最多在 `chrome://extensions` 点击一次「重新加载」 |
| 选择「打开浏览器」没有反应 | 这个按钮只在 Desktop 里出现；它会打开上次承载扩展的那个浏览器（未记录时使用 Chrome）。如果打开后仍然连不上，请检查扩展是否被禁用 |
| 提示连接了多个浏览器账号 | 每个浏览器账号各有一个扩展实例，工作台不会自行猜测。请按页面上给出的命令列出账号，并选择一个默认账号 |
| 页面工具是不是在 Desktop 里都不能用 | 不是。调试与日志那两族不提供；页面族还在，带站点地址的只读入口可以读取页面，录制、面板与状态照旧。不带地址的看 / 点 / 网络会拒绝并说明原因 |
| 面板一直空白 / 持续加载 | 请依次确认：这个工作区已安装模块、要查看的平台已登录、「准备工作台」里「连接浏览器」那一行显示已连接；第一次加载可能需要几秒 |

## 界面不对

| 症状 | 怎么办 |
| --- | --- |
| 左栏恢复出厂、右侧面板消失 | 插件被关闭了。打开 Settings → 插件，重新启用 `@dsh-workbench/core`；如果进不去，按 `Meta+,` |
| 左栏没有「工作台 DIY」、模式里也没有「工作台 DIY 模式」 | 通常是 dsh 版本太旧：DIY 模式在启动时按「工作台设置 → DIY 模式继承自」选中的模式创建（默认标准模式），旧版本不支持创建工作台自己的模式，所以整个入口不会出现，也不会报错。选中的模式不可用时，DIY 模式会退回标准模式；标准模式也不可用时同样看不到入口。「准备工作台」会指出这一点并给出升级命令，升级后重启 |
| 打开面板 / 按刷新要等 5–8 秒 | 正常现象：opencli 每次调用都有固定开销，数据一律实时读取、不使用缓存 |
| 页面白屏 / 提示插件加载失败 | 通常是插件冲突。请重启 Desktop 并检查插件开关；仍未解决就到仓库提交 issue |

## 数据对不上

- 会话、项目、附件放在 `~/.dsh` 下，安装或卸载工作台都不会修改它们。
- 设置与插件沿用 Desktop 的那份配置；工作台自己的开关另存在 `~/.dsh/workbench/settings.json`，只影响这份工作台。
