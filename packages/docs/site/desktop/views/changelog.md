# 更新日志

仓库从这一版开始记录：`v1.1.1` 是这份历史的第一个版本。

## v1.5.6

`2026-11-27`

这一版把 DIY 模式收紧成一条按步走的路：工具包按步骤开、方案批准之后成为交付基线、流程状态跨会话接着
走，技能文档按「什么时刻读哪份」重写。长任务由模块声明一次计划，步数由外壳自己数，进度条与收尾十分钟
一并补上。启动页的故障卡统一成「原因 + 怎么解决」，模块构建完直接推回工作台，不用再等轮询。另修好
opencli 2.x 的命令面按索引读，以及侧栏的状态点与工作区分组。

### ✨ 新增

- **DIY 的工具按步骤开包**：DIY 会话默认只开 `diy-flow`（6 把：状态 / 计划 / 步骤 / 面板 / 查已安装
  模块）；走到 `probe` 步开 `diy-probe`（2 把），`build` 步开 `diy-build`（9 把，含安装、发布、显示
  与长任务），`verify` 步开 `diy-page`（17 把）。`diy-debug` / `diy-record` 只能手动开。只增不减，流
  程结束一次收回；手动开的包不收回，手动收的也不会被开回来。调到已收包里的工具会被拒，报错写明它属于
  哪个包，并给出 `workbench_toolbox_open`（`targets` 填这个包）；这一步本来就要用它时，
  `workbench_diy_plan` / `workbench_diy_step` 的返回末尾会补一句。`write` / `edit` 只在「创建模块」
  与「保存这次的设计」两格放行，DIY 会话里没有 manage 包可开。

- **长任务的计划只写一次**：`create` 时给 `plan`：`{ steps: [{ id, title? }] }` 或只给 `{ total }`。
  起点就是 0/N，`done` 由外壳按 `stepId` 数 —— 同一个 id 的最新状态成功算走过（重试一次、跳过也
  算），只增不减，超过 `total` 夹住，成功铺满，失败与停止停在最后值；模块不用自己报 `done`，
  `onProgress` 仍可用、与计划并存时优先。给了 `title` 的步骤，展开区把还没开始的也列出来（灰点，没给
  `title` 就写 id）；不写 `plan` 的模块照旧，没有进度就不画条。一趟里见到三个不同的 `stepId` 却始终
  没有进度时，注册表只告警一次。

- **收尾的长任务行留十分钟**：完成后在左栏留 10 分钟；轮询从 1.5 秒退到 10 秒，最迟 10 分 10 秒退
  场。打开「工作台任务」面板即对没看过的收尾行发 `<单元>/runs/seen`，清掉选择器上的「N 个长任务已完
  成」、触发器上的「已完成」与会话行的点，行本身仍留满十分钟；对还在跑的这条请求回「这一趟还在运行，
  结束后才能标记为已查看。」，重复发不刷新时间。

- **流程状态跨会话接着走**：DIY 流程写成一条 `plugin:workbench/diy-flow` 记录（version 1，投影名
  `workbenchDiyFlow`），`turn/start` 不清空；重启、`--resume`、fork 之后回到同一步与已经填过的值，恢
  复时不追加一条 running 快照。只有 running 且这一格认得出才恢复：done / stopped、版本或流程 id 不认
  识都算没有流程。

- **`/workbench` 根入口**：`/` 菜单里常驻 `/workbench`（没有项目时也在），正文只说用 manage 与
  diy-flow 两族工具包，不点名具体工具；它只给人用，模型看不到，和 `/workbench-<模块>` 并存。配置变化
  后重新列出，不失效。

- **模块构建完直接推送**：`dsh-wb-module build` 成功后往 `<工作台根>/diy/outbox/<模块>.json` 落一条
  `{ unit, dir, at, files, pid }`，工作台用 `fs.watch` 盯着这个目录，收到即对账配置并换上模块；换的
  是模块本身，不整页刷新；带上 `dir` 之后，模块仓库放在工坊外也照样换。构建失败不推送、旧模块照旧
  跑；对账没成就按 600 毫秒乘失败次数退避重试。`--watch` 盯 `src/**`，停手 120 毫秒就重建并推送；
  `dsh-wb-module status` 多一行「最近一次推送：已生效 / 未生效（原因）」，不再拿产物修改时间猜。

### ⚡ 改进

- **已批准的方案成为交付基线**：方案批准之后（四段说明 + 界面预览 + 审批四格）成为基线，`plan` 与
  `step` 的返回都能读回；走到「保存这次的设计」时逐段比模块说明，不一致就点名哪一段缺哪一条，并给出
  「改说明」或「带新 summary 重走方案」两条路；没有基线的旧流程放行并注明。去向写进流程即锁定：
  `summary` 变了默认拒绝，带 `restart: true` 才从头来。建看板与改模块至少一张非审批图，有写工具时必
  须同时给审批四格与一张 `kind: "approval"` 的审批屏。

- **进度条只在有总量时画**：条固定在正文最后一行：普通档 4px，行尾跟 `3/7`；窄栏列表里 2px，`3/7` 并
  进「运行中 · 8 秒 · 3/7」。`total` 不是正数、`done` 不在 `[0, total]` 就整根不画，不把坏数字夹成好
  数字；色档按成功、失败、停止、等人、运行中五档取。条抽成 `@dsh-workbench/shared` 的 `ProgressBar`
  （6 / 4 / 2px 三档），卡片指标条改用 6px 档，读数与外观不变；左栏会话列表的跑马灯逻辑搬进同一个包
  里的 `useTextMarquee`，行为不变。

- **审批的「修改后」「影响范围」可以写多行**：这两项可以传数组，一项一行，最多 6 行；「修改项」「目
  标位置」仍单行。超限时点名是哪一项、给了几行，并提示更多内容放 `approval.render`。

- **启动页故障卡统一成「原因 + 怎么解决」**：标题下面先「原因」再「怎么解决」，多步做法自动编号；认
  不出原因时换成兜底卡，标题是「需要 agent 诊断」、下面列「现象」。命令行是一段代码加复制按钮，复制
  后变对勾、1.5 秒恢复，没有命令时整行不显示；桌面版的扩展卡多一个「打开浏览器」，兜底卡多一个「复制
  给 agent」（复制后按钮显示「已复制」）。覆盖安装失败、浏览器、DIY 与 dsh 版本四类，浏览器扩展按有
  没有本地副本分三种做法。

- **DIY 技能按时刻重写**：入口 `SKILL.md` 从 184 行收成 69 行，只留分诊（九类去向）、流程选择与跨入
  口规则，每个去向按「首读」列指到一份文档。流程节点表搬进 `FLOW.md`（`diy-board` 6 格 / `diy-tweak`
  5 格 / `diy-write-record` 4 格，每格列手里 / 做 / 交 / 完 / 读 / 卡），症状查表进 `SYMPTOM.md`（每
  条四格：先查什么 / 怎么判 / 结论 / 转哪），模块生命周期进 `LIFECYCLE.md`（每条五格）；旧 `FLOW.md`
  改名 `WORKFLOW.md`。11 份文档删掉 `workbench_diy_surface name=<名>`、`scope: 'tokens'` 这类按名字
  查的写法，改成读声明与 JSDoc；审批四行改指公开类型 `ApprovalPlanData`。新判据盯覆盖：去向缺一、节
  点与代码顺序不一致、六格缺一都会点名到文档行。

- **插件单元的技能名用插件名**：新增 `skillId`：插件单元可以给自己的技能名一个 `skillId`，不写就用模
  块 id（例如 `/workbench-grafana`）。只收 `^[a-z0-9]+(-[a-z0-9]+)*$`，不合规不自动改名，这个入口直
  接不出现，且只警告一次。

- **门禁跑完再汇总**：`pnpm run check` 走 `node scripts/gate.mjs`：20 步默认全部跑完再汇总，每项附末
  尾 6000 字与 ✔ / ✖ / ○；`--fail-fast` 恢复第一个失败就停，`--only a,b` 只跑指定步骤，`--list` 列出
  步骤；`build` 红时依赖它的 8 步标「未运行」。链只有 `scripts/gate/steps.mjs` 一份定义，
  `AGENTS.md`、`CONTRIBUTING.md`、`ARCHITECTURE.md` 跟着改。

- **自检与测试按机器分片**：module-tools 自检的判据轮转分片，默认 `min(4, 核数 / 2)`，
  `--shards 1..16` 可指定；测试并发按「包数、核数 / 2、内存 GB / 2、6」取最小，CI 上限 3，
  `WB_TEST_CONCURRENCY` 可覆盖。

### 🐛 修复

- **opencli 2.x 的命令面按索引读**：2.x 的 `list -f json` 只回 `{ command }` 索引，按 1.x 的行形状读
  会读不到站点与参数。现在逐个插件问 `<site> --help -f json`，取 browser、domain 与参数；1.x 里带
  site、name 的行照旧处理；某个插件的站点说明读不出来时点名它、这次不把它合成工具；两种形状都不认才
  整体失败。

- **侧栏三处**：状态点（长任务入口、面板图标、项目切换器三处）都贴到 `svg` 的右上角；窄栏的长任务入
  口改成 36×36 的图标按钮，运行中由 8px 的转圈改成同尺寸蓝点呼吸 1.5 秒，没有待看任务时不显示点；
  「工作台任务」里的工作区分组标题变成按钮，点它跳到该工作区当前的会话，没有会话才按原规则新建；窄栏
  里的长标题允许折行、行高自适应（至少 24px），状态与耗时仍在同一行右侧。

## v1.5.5

`2026-11-26`

这一版给有工具的模块一个入口：在 `/` 菜单里选 `/workbench-` 加模块标识，就能让 agent 用这个模块的
工具包做事，不用记工具名。工作台工具的输出不再由各工具自己截断：超过上限的整份存成文件，模型只看
头尾与路径。模块作者查能力的 `surface` 能一次问几个名字、按类型名取声明；模块市场的「有新版本」
不用打开市场也会亮。单模块发版只跑自己的检查，不再被兄弟模块的问题挡住；Windows 上一处探测在锁目录
正被删除时也能继续等。

### ✨ 新增

- **`/` 菜单里多一个模块入口**：安装完成、在当前项目启用的模块只要有工具，`/` 菜单里就有
  `/workbench-<模块标识>`（例如 `/workbench-gitops`）；可以带上任务，交给 agent 的是模块名与工具包
  `unit:<模块标识>`，不点名具体工具，agent 自己打开这个工具包；不带任务就让它先看看这个模块能查
  什么。它只给人用：模型看不到这些条目，也不会自己触发；模块或面板配置变了，这份目录随之失效，
  不用重启。
- **模块市场在后台查更新**：启动 60 秒后查一次，之后每小时一次；页面不可见时不查，回到可见且距上次
  已满 10 分钟就补一次（桌面端窗口失焦也算，不只看 `visibilitychange`）。查到之后「有新版本」直接
  亮在模块市场入口上，不用打开市场；你在市场里点过「检查更新」也算一次，10 分钟内不会重复查。查失败
  只写一条警告，下一次的排期照旧。
- **`surface` 一次可以问多个名称**：`name` 用逗号、中文逗号或空格分隔，最多 8 个，每段各自带声明与
  JSDoc。还能直接 `name=<类型名>` 查公开类型（如 `UnitSeam` / `CardProps`）；问 kit 成员时一并给出
  它的 Props / Options 类型位置，问 deps 成员时给出它的字段类型。

### ⚡ 改进

- **工具输出的上限改由工作台统一把关**：单次返回超过 8192 字（按码点算）就整份存成文件，模型只看到
  前 4096、后 1024 与文件路径，能用 `read` 的 `offset` / `limit` 或 `grep` 接着看；没有可用存储时
  改成截断，并写明省略了多少字节。只对经工作台登记的工具生效 —— 模块工具与面板工具各走一条注册
  入口，DIY 步骤工具的注册也并回这条入口。`surface` 与令牌工具里自行截断与「会被修剪器裁掉」的
  告警删掉，字段级预览保留。
- **工具包的说明分成两处**：`workbench_toolbox_list` 的描述退回「是什么 + 什么时候调用」，优先级那句
  （先用工作台工具，不确定开哪个包就先 list）搬进系统提示词段 `workbench:tool-priority`（order 700，
  每个会话注入一次）；flow 子 agent 的工具面里没有这三把控制工具，这一段给空；没有 systemPrompt 服务
  时只记一条日志。
- **撤掉运行期的能力索引**：不再按 agent 注册一份 `workbench-capabilities` skill；发现的途径只剩三把
  控制工具里的最小索引、失败转发现与按需的 `workbench_toolbox_list`。它原先只省一次 `list`，却要按
  agent 重复注册、失败只留一行日志，包一多描述还会被 skill 目录的 500 字上限截断。
- **单模块发版只跑自己的检查**：`check --package` 从「报告过滤器」变成单模块的检查范围 —— 十五条检查
  项只在目标模块上运行，不再靠报错文本前缀猜归属。单元 id 重复、供应来源冲突、工作台源码点名模块这
  三类工作区级不变量仍按全工作区校验，并在 `contracts` 里一次报出全部声明者。`release` / `publish`
  固定跑这一档，兄弟模块的文案、审批、卡片、lint 问题不再挡住本模块发版。
- **kit 与 deps 的说明住进声明**：deps 的子孙成员与入口选项补齐 JSDoc，kit 里逐字段的 `@param` 迁到
  成员自己的声明上，`surface` 按类型一查就能看到用法、默认值与边界。公开类型统一登记到
  `public-types` 表，工作台自检按这张表核对。
- **模块作者文档补齐审批与字数**：`COPY.md` 的审批段改写成 `headline` 加四行 `plan`，写明只有没有
  `headline` 的旧模块才用「允许吗」整句；补一张位置与上限的表（模块标题 12 字、审批标题 15 字、审批
  明细 20 字、审批问句 40 字）；词表收进作者会写的界面词，内部词清单补全，并修掉一处指向
  `PANEL.md` §7 却写着别的内容的引用。`AI.md`、`BUILD.md`、`TOOLS.md`、`WIRING.md` 里与声明重复的
  签名删掉，改成 `name=<类型>` 指路。词表与 `.agents/skills/wording/TERMS.md` 的同源由文档事实检查
  盯着，缺一条就点名 `COPY.md` 的行号。

### 🐛 修复

- **Windows 上锁目录正被删除时不再误判没权限**：安装工具链时「另一处正在装，等锁」这一步，锁目录被
  `rmdir` 挂起期间 `mkdir` 报 EPERM，而此刻 `stat` 也看不到它，旧逻辑当场判成真没权限、探测失败。
  现在这两件事同时发生时先给一段宽限（默认 2 秒，`absentGraceMs` 可调）：宽限内锁放开了就继续，
  一直看不到才照原样报错。

## v1.5.4

`2026-11-25`

这一版补全长任务：每一步可以带「去哪看」的链接，行上直接给出当前步骤、状态词与耗时，同一步的进行中
与结果收成一行；左栏底部多一个「工作台任务 N」入口，按工作区、单元分组列出所有单元的长任务，还在
等你处理的排前面。模块可以把长任务行放进自己的界面，也可以只在自己的那一行下面挂一条；同一个单元的
长任务只轮询一次，卡片与模块自己的界面共用一份读数与一套停止 / 重查 / 回执状态。另外修好了在程序里
调工具时审批详情整格空白。

### ✨ 新增

- **长任务行上直接给进度**：运行中与停止后，标题下给一行当前步骤；行尾写「状态词 · 耗时」，状态词
  按六态取（运行中 / 等你处理 / 需要登录 / 已停止 / 已完成 / 失败），耗时不足一分钟写秒、不足一小时
  写「分 秒」、再长写「小时 分」。点过停止之后、模块确认之前，行下显示「已请求停止，等模块确认」。
- **步骤可以带链接**：每一步可带 `links`（`{ href, text }`，最多 3 条，只认 `http(s)`），画在步骤
  行尾；流程里用 `ctx.log(text, links?)` 给。长任务行尾也能带产物链接，与卡片覆盖按 `href` 合并
  去重。
- **左栏底部多了「工作台任务 N」入口**：只要有长任务就出现，宽栏显示文字、窄栏只留一个点；打开后是
  「工作台任务」列表，按工作区 → 单元两级分组，工作区显示末段与总数，没有卡片的单元的长任务也在
  这里。有等你处理或需要登录的，入口上的点变成提醒色。
- **模块可以把长任务行放进自己的界面**：新增 `LongTaskRun`（一条，放进模块自己的 DOM）与
  `LongTaskSection`（一个单元的全部）；读、停、重查、回执、登录、打开链接都接好。卡片行也能只挂
  一条：给 `CardViewRow.longTaskTarget` 一个 `target`，属于它的长任务画在这一行下面，其余的仍在
  卡片的长任务区。

### ⚡ 改进

- **同一步的进行中与结果收成一行**：按 `stepId` 归并，结果覆盖进行中；`attempt` 大于 1 时写明
  「第 N 次」；`info` 走细节行、不占状态点。不传 `stepId` 的模块照旧逐条平铺。快照另攒一份结构化 `history`
  （与 `steps` 同源、同去重、同 20 条上限），旧消费者照旧读 `steps`。
- **同一单元的长任务只轮询一次**：`useLongTask` 按 `(unit, workspace)` 单飞，卡片、模块自己的

  过期信号、会话、超时、信封、分页），配方与读取计划只写 `site: '<短名>'`，不必每一处都抄 origin
  与登录页。`dsh-wb-module sync` 生成 `src/sites.ts`，并把相对信封的路径展开成绝对路径；没有站点表的
  旧模块照旧写内联 `origin`。

#### ⚡ 改进

- **没有看板的模块也走同一条流程**：六步照样走，安装那一步叫「安装模块」，检查那一步叫「检查模块功能」，
  确认方案那一步不画字符画。
- **工坊里的工具与审批更集中**：工坊会话默认只开 DIY 一个工具包，管理包不再列出（安装模块、卸载、
  看市场、长任务都在 DIY 包里）；安装自己刚做的模块、显示在看板、隐藏模块不再弹审批，安装从市场来的
  模块、卸载、占用屏幕、发布仍然问。
- **模块的工具不再有常驻**：不管有没有卡片，工具都收在工具包里，用之前开包（要用户批准）；清单里
  去掉 `onDemand`，旧清单还写着的仍能加载，`dsh-wb-module check` 会给一条提醒让删掉。
- **工作区列表把要处理的事排前面**：等待批准的整段上浮，组内按待审批、新消息、运行中、无状态的
  顺序排，同一档按最近活动；打开后顺序固定，点的时候不跳位；不足四条不画组标题，搜索时平铺。
  选择工作区的开关悬停时出现三点，点它打开与列表行相同的菜单；在开关上点右键也会打开。
- **读数据能停、能看清受阻于哪一跳**：`data.plan` 接 `signal`，停止长任务会中断运行中的页面读；
  每跳带 `elapsedMs`，长任务行给一条耗时摘要；同一会话的读串行，避免互相踩。
- **流程里直接写数据步骤**：`{ data: RequestPlan }`，结果摊平到 `steps.<id>`；登录失效且计划给了
  `loginUrl` 时进「等你处理」带登录链接，登录后原地重试（没给 `loginUrl` 直接失败）；`poll` / `forEach` 不开放。
- **适配器协议升到 v2**：`DataReader.plan` 与 `submitPlan` 都是必备成员；v1 集合要补两者并升 `apiVersion`。
- **读取计划能分页、读表格、落附件**：`repeat` / `while` 最多 50 轮；`response.kind: 'html'`
  直接按 `selector` / `fields` 取表格；
  `bytes` + `saveAs: 'attachment'` 把二进制交给宿主附件服务，结果换成附件引用。
- **写计划有逐步骤确认与幂等键**：`submitPlan` 只在每步确认后写，GET / 分页直接拒；
  写失败不重试，后续步骤标 `skipped`，附件和长任务都能接。
- **模块要读哪些站，装之前先看**：`host.origins` 声明站点根；运行期 `deps.data` 只放行声明过的 origin，
  path / registry 安装预检直接列出「会读取这些站」（git 源装前读不到清单）。不写仍按旧模块放行。
- **更新被打断也能收尾**：更新前先写一份记录（从哪个版本换到哪个、每个包指向哪里），起工作台之前
  按它把没做完的更新补完，或退回上一个完整的版本，已提交的只清记录；换完链接之后再复检一遍版本目录，
  不齐就按记录回到上一个版本。更新与依赖重装不会同时进行，同一时间只有一个进程执行。
- **依赖重装失败会重试，连续三次停下**：下次启动时自动重试；连续三次失败就停止自动重试，模块市场
  那一行提示重装失败，下一步是手动重装。

#### 🐛 修复

- **热替换模块后长任务仍在使用旧实现**：改完源码重新加载后，运行中的那条长任务使用的是旧闭包；
  现在注册表会切换到新实现，历史记录与运行中的那一条都保留。
- **改完没有生效时状态里会说明**：产物比运行中的实例新时，模块状态直接写「产物比运行中的实例新：热替换没有生效」，
  不需要再判断是否漏了重新构建。
- **三点菜单的项点了没反应**：菜单原来挂在按钮上，点菜单项时按钮先被收起，菜单跟着关掉；现在按打开
  那一刻的位置定位，菜单项点了就生效。

### shared

#### ✨ 新增

- **流程可以一步一步由外部推进**：流程宿主新增 `open`（与 `run` 同级）：`current()` 给出现在停在哪一步，
