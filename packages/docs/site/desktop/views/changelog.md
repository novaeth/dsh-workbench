# 更新日志

仓库从这一版开始记录：`v1.1.1` 是这份历史的第一个版本。

## v1.2.11

`2026-11-13`

### core

#### 🐛 修复

- **模型能正常读取工作台能力**：加载「工作台能力」清单时会报错，模型拿不到当前能开的工具包；
  现在能正常加载，开包前就知道有哪些包可选。
- **点「更新」不再把工作台换成旧版**：更新第三方模块失败时，工作台以前会把自己换成和那个模块
  同号的旧版本；现在更新不成就给出可复制的修复命令，工作台本身不动。
- **刚发布的模块能正常安装和更新**：pnpm 默认会挡掉 24 小时内发布的新版本，模块更新会因此
  失败、还看不出原因。现在工作台自己的包不再受这条限制。
- **更新之后旧版留下的组件会被清掉**：这一步以前每次都失败，旧版带进来的 dsh 包一直留在
  工作台里；现在会正常清掉，不需要再手动修一次。
- **设置页的分组箭头方向对了**：收起时朝右、展开后朝下；之前两种状态都朝下，看着像还能再展开。

#### ⚡ 改进

- **更新后自动清理旧版本**：每次更新只保留当前版和上一版，更早的自动删除，不用再自己去删文件夹；
  还在使用的旧版本不会被删。

## v1.2.10

`2026-11-13`

### core

#### 🐛 修复

- **启动检查不再把旧运行时当成可用**：只有入口文件和版本号都对得上才算就绪；能运行但版本不对会
  走修复流程，不再一直用着旧副本。
- **运行时安装失败不再留下半套文件**：先装进临时目录、自检通过再切换；中途失败保留旧副本，
  残留在下次安装时清掉。
- **启动检查与安装不再同时进行**：两者排队执行，不会重复安装，也不会因为另一处正在安装就显示
  失败页。
- **启动不再删除 pnpm 的授权文件**：配置文件交给 pnpm 维护，安装与启动不再来回改写。

## v1.2.6

`2026-11-12`

### core

#### ⚡ 改进

- **dsh 依赖升到 0.2.2-rc.2**：官方包整体跟进，最低支持版本同步改成 `>=0.2.2-rc.2`；两处被新版本
  撤掉的旧用法按新接口改好。
- **市场页改版后的自动检查**：检查先切到「已安装」页再找「添加模块」，失败时把页面现场写进附件。
- **慢机器上的停止测试更稳**：不再把晚到的写入当成没停。

#### 🐛 修复

- **升级 dsh 后启动失败**：工作台配置里留下的运行时代码与 dsh 不是同一代时，插件会逐个被停用，
  最后只剩一句「N 个必需插件未激活」。现在官方包只留在开发依赖里，安装工作台或模块时不再带
  第二份 dsh。
- **更新后旧文件真的会被清掉**：以前更新完只同步版本记录，旧版带进来的 dsh 包留在工作台配置里，
  升完 dsh 仍可能启动失败；现在换版之后按新依赖重装一次。
- **启动前先做一次只读对账**：启动器比较工作台配置里与运行时同名的 dsh 包，不同代就拒绝启动并
  提示重装，不再等到运行中才发现。
- **模块只拿工作台自己的类型**：公开的模块接口不再导出 dsh 的类型；需要官方类型的模块自行放进
  开发依赖。模块模板与示例模块已同步。

#### 🗑️ 移除

- **撤掉「立即重启」与「稍后」**：更新完成后只留「重启后生效」，重启由用户自己退出再打开——
  那颗按钮在新进程启动失败时会让用户手上什么都不剩；「稍后」也只是把它收起来，没有下一步。

## v1.2.3

`2026-11-12`

### core

#### ✨ 新增

- **工具包按需加载的能力清单**：三个控制工具的说明里补上一张「什么需求开哪个包」的地图；模型调用
  已收起的工具时，会被告知它属于哪个包、下一步开哪个，审批之前就生效，不会先批准再失败。创建

- **浏览器扩展可以离线安装**：扩展随工作台自带一份；启动检查给出两种安装方式（用自带的副本，或
  从 Chrome 应用商店安装），没有外网时给出三步手工加载说明。

#### ⚡ 改进

- **设置页按官方行重排**：会话列表、MCP 按需加载、检查预发布版本改成一行一个开关；配置同步与
  新建工作台收进「高级」折叠区；新建工作台的结果给出可复制的启动命令。
- **更新改成装进独立目录**：新版本装进 `versions/<版本>`，工作台配置里只切换指向它的链接，换版本
  不再重装、也不需要等退出后再换（第一次迁移除外）。
- **更新状态只留三种**：「正在更新」「重启后生效」「更新失败（再点一次重试）」，不再展示原因分类
  与恢复方法原文。
- **启动页只重试失败的那一步**：不再从头运行一次检查，前面的结果直接沿用。
- **dsh 版本下限抬到 0.2.2-rc.1**：仍停留在更老版本的实例会先被启动器阻止并给出升级命令。
- **界面与工具文案按句重写**：中英双语按句级统一，日志与命令行的用词同源；新增文案检查并接入
  门禁。

#### 🐛 修复

- **启动即插件加载失败**：界面停在插件页，原因是客户端用到的几个服务没声明；现在补齐声明，读取
  仍按「有就用、没有就退」处理。
- **Windows 上可以安装插件**：第三方安装的子进程不再被系统拒绝；找不到 pnpm 时先用 Desktop 自带
  的那一份。
- **更新检查不再退化成「最新版」**：官方 Desktop 的 node 不带 npm，版本探测无效、更新永远显示
  「已是最新」；现在改为两条探测路径，读不到时按频道取版本而不是回落到稳定版。
- **安装失败给出原因**：「添加模块」的失败页画出标题、原因与失败那一步的完整命令，底部可以
  「更换安装源」或「重试」。
- **市场行不再自相矛盾**：还没更新时不会同时显示「重启后生效」和「有新版」。
- **启动遮罩不会自己关掉**：停在启动页读原因、复制安装命令时，遮罩不再到点自动消失。
- **检查更新不再被慢速来源拖住**：查询超时放宽，失败结果只短暂缓存，不会一次超时锁死后续检查。
- **自更新中断不再停在「更新中」**：中途崩溃会写成「更新失败」并给出恢复方法。

#### 🗑️ 移除

- **移除版本回退**：市场行不再提供「切回上一版」，自更新也不再自动回滚。实际使用中误判多于补救
  ——更新后停在插件页、客户端尚未挂载时会被判成没启动，超过宽限期就把新版切回旧版。

### docs

#### ⚡ 改进

- **文案规范成文**：新增语域与词表两份文档，重写写作指引与各读者分册。
- **文档按句级重写**：README、文档站的安装 / 快速开始 / 常见问题 / 数据 / 模块 / 架构页按新规范
  重写。
- **版本与门禁口径同步**：README 与快速开始里的 dsh 版本号跟着改；升级说明改成「装进独立版本
  目录、重启后生效」，并注明第一次更新前 Desktop 需要先退出。

## v1.2.2

`2026-11-10`

### core

#### ✨ 新增

- **工作区行的更多菜单**：行尾改成三点菜单：设置别名、在 Finder 中显示、删除工作区；右键打开同一
  份菜单。删除要二次确认，只把工作区从列表移除，文件夹与会话记录保留；别名只改显示名。

#### ⚡ 改进

- **门禁不再依赖开发机环境**：字号判据改用外壳自带刻度，全新机器上不再误报；整链之后再用一个
  干净的数据目录运行一次自检。
- **自动检查覆盖更多场景**：新增每次推送与每周的整链检查；失败时把关键错行连同判据明细做成注解。

#### 🐛 修复

- **Windows 升级后浏览器取数不可用**：升级后隔离运行时被判定「尚未安装完成」，取数、插件与依赖
  浏览器读数的面板全部不可用；现在缓存位置只有一个来源，装失败会清掉重装一次。
- **独立实例的端口写进自己的配置**：直接运行时不再回落到 dsh 默认端口，避免和 `dsh web` 冲突。
- **Windows 上的自更新与内置命令**：子脚本按平台执行，命令探测不再受别名影响，未移植的命令给出
  明确说明。
- **Windows 上的路径与配置文件**：带空格的路径、反斜杠、换行符都按平台归一，给用户的命令不再带
  多余前缀。
- **写域按真实路径判定**：`/tmp` 这类别名与大小写差异不再把域内路径判成域外；不可写的目录在运行
  前就被拒绝并说清权限。
- **超时与取消终止整个进程树**：返回后子进程不再继续写文件。
- **会话「更多」不再打开空菜单**：右键与快捷键打开同一份菜单。
- **工作区菜单的开合与关闭**：打开菜单时选择器不再收起；关闭由菜单自己处理，Escape 只关菜单。
- **写入失败时对话框仍可关闭**：失败后可以关掉对话框重试。
- **共用依赖行与模块行一致**：状态点与更新按钮跟模块行对齐。

### docs

#### ⚡ 改进

- **安装说明补上端口与 Windows 限制**：两种启动方式用同一个实例、同一个端口；Windows 上独立实例
  的启动器还需要 bash，可改用 `dsh web` 或 Desktop 的插件页。

## v1.2.0

- **空态统一用插画**：看板、模块页与市场都改用 dsh 的空态插画。
- **品牌标重画并改纯色**。
- **安装审批列出要装的依赖**：读不到声明、没有依赖时分别给出说明。

#### 🐛 修复

- **卡片动作与阻断重排**：动作统一排到右下角，阻断详情排在动作之前；未知错误给出看得懂的说法，

- **模块**：声明协议到 v3，模块可以直接写中英名称；构建、安装、升级、卸载与判据由模块工具包负责。
- **迁移**：从 1.0.0 之前的独立实例升上来，运行 `dsh-workbench migrate`，或在模块市场点「迁移旧数据」。
