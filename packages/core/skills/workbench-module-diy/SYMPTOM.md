# 查：按症状取证，再给结论

用户要结论时从本页开始；查的过程不改源码。确认需要改动后转 [FLOW.md](FLOW.md) 的 `diy-tweak`，安装、生效与重启问题转 [LIFECYCLE.md](LIFECYCLE.md)。不要要求用户截图或转述技术报错。

默认先走 `workbench_diy_panel`、`workbench_diy_status`、带站点地址的只读页面查询与直接路由请求。只有必须复现真实交互时才申请 `workbench_diy_debug_start`，说明占用范围与时长；结束用 `_debug_stop`，暂不查看用 `_debug_pause`。Desktop 没有页面调试与日志族，仍可用只读线；无法确认的项目写成未验证。

## 没显示

- **先查什么**：`workbench_diy_status`（带模块标识），看安装、识别、当前项目是否显示、产物与下一步。
- **怎么判**：未安装是安装问题；已安装但未识别看启动状态；已识别但未显示是面板状态；都已满足才查页面是否仍展示旧内容。
- **结论**：归为装载、识别或面板显示；「安装完成」不能代替识别与显示状态。
- **转哪**：按 [LIFECYCLE.md](LIFECYCLE.md)「装完没出现 / 已装未识别」处理；已显示但内容异常继续查「空白」。

## 空白

- **先查什么**：`workbench_diy_panel`，看该模块的读取状态、宿主错误原文、崩溃原因与次数。
- **怎么判**：有宿主错误先直接请求对应路由；路由正确而卡片空白或崩溃归渲染，路由错误归宿主或数据源；面板没有运行态时，请用户切到对应工作区并刷新页面，然后重新调用 `workbench_diy_panel`。
- **结论**：明确是宿主、渲染还是数据源，并引用读到的状态或路由结果。
- **转哪**：需要修代码就转 `diy-tweak`；构建后仍空白转 [LIFECYCLE.md](LIFECYCLE.md)「构建成功但没生效」。

## 数错

- **先查什么**：`workbench_diy_panel` 看读取状态，再直接请求该格路由，与同站点同一口径的原始值对照。
- **怎么判**：路由与原始值不一致是数据源或口径；路由一致而卡片不一致是渲染；操作后路由已新、卡片仍旧是联动；各方一致但用户预期不同是需求变化。
- **结论**：说清错在数据源、换算、渲染、联动还是需求口径，给出对照值与来源。
- **转哪**：实现错误转 `diy-tweak`；只是要新口径也转 `diy-tweak`，但先重新确认方案；旧值继续看下一节。

## 旧值

- **先查什么**：`workbench_diy_panel` 看当前读取状态，再直接请求路由比较新值；刚发生写操作时核对这次写认领了哪个事实。
- **怎么判**：路由仍旧是数据源未回读或缓存；路由已新而卡片旧是事实订阅或失效范围；切换项目后旧值残留是工作区联动。
- **结论**：归为数据源、联动或渲染，指出哪一格与哪个最窄参数没有更新。
- **转哪**：按 [LINKAGE.md](LINKAGE.md) 核对事实名与刷新粒度；需要修改转 `diy-tweak`，程序更新后的旧页面转生命周期。

## 按钮失败

- **先查什么**：先用 `workbench_diy_panel` 排除模块已崩溃；必须复现时调 `workbench_diy_debug_start`，再查看按钮状态、点击结果与网络请求。
- **怎么判**：按钮不可用看当前状态与配置；点击无请求看动作绑定；请求被拒看审批与参数；请求成功但界面不变看回读与联动。要捕获用户点击实际发送的内容时，用 `_record_prepare` → 用户操作 → `_record_read` → `_record_detail`。
- **结论**：归为界面状态、动作绑定、审批、宿主写入或联动，并保留实际请求结果。
- **转哪**：需要修改转 `diy-tweak`；审批被拒或中途取消转 [LIFECYCLE.md](LIFECYCLE.md)；页面调试结束调用 `_debug_stop`，录制取证按 [FLOW.md](FLOW.md) 推进到 `finish` 后再调用 `_record_stop`。

## 长任务停住

- **先查什么**：`workbench_long_tasks_list`，看这条运行的六种状态、当前步骤、最近事件与人工介入信息。
- **怎么判**：等待登录或人工处理不是运行失败；失败看失败步骤与原始输出；运行中但长时间无新事件才查轮询、子命令与停止信号；已停止就不再等待它自行推进。
- **结论**：归为等待用户、数据源、模块编排或已取消，说清当前停在哪一步。
- **转哪**：需要用户处理就只给那一步；实现问题转 `diy-tweak`；用户要停止或取消转 [LIFECYCLE.md](LIFECYCLE.md)。

## 流程停住

- **先查什么**：`workbench_diy_status`，看当前流程步、下一步与工具包提示；不要用提交工具空试来探测。
- **怎么判**：等待方案材料就补方案；等待当前节点字段就按返回提交；工具包被手动收起按提示处理；需求或去向已变则当前流程不应继续前进。
- **结论**：归为等待输入、等待用户、工具包或需求变化，不反复调用同一被拒工具。
- **转哪**：按当前节点回 [FLOW.md](FLOW.md)；缺包、审批或取消转 [LIFECYCLE.md](LIFECYCLE.md)；面板症状留在本页继续查。

## 页面是旧版

- **先查什么**：`workbench_diy_status`（带模块标识），看源码是否新于产物、是否收到构建推送、变更是否已应用。
- **怎么判**：源码较新是没构建；产物较新但未应用看推送与待重启原因；宿主变更已应用而客户端仍旧才需要刷新页面。
- **结论**：归为未构建、未推送、待重启或客户端未刷新，不把「构建成功」说成「已经生效」。
- **转哪**：直接转 [LIFECYCLE.md](LIFECYCLE.md) 的对应条目；生效后仍有显示问题再回本页按具体症状查。

## 需要更深取证时

1. 直接请求路由：接口正确而卡片错误归渲染，接口错误归宿主或数据源；页面内请求用带站点地址的 `_eval`。
2. 控制台用 `_logs_watch` → 操作 → `_logs_read`，结束用 `_logs_stop`；`opencli browser … console` 是空桩，不作为证据。
3. 页面工具作用域与参数保持工具定义原样；宿主热换与装载错误还需看启动工作台的终端。
4. 已有结论就停止扩工具范围；每一次查询都要改变判断或给出下一步。
