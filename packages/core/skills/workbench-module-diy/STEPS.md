# 确认方案：问什么、何时算完

只用于 [FLOW.md](FLOW.md) 的「确认方案」节点。每次询问都给推荐答案；用户只决定看到什么、能做什么与哪些操作需要批准，实现由 agent 决定。

## 面板

**只问两句**（给推荐答案；问完就出图，用图继续问）：

- 打开面板时，你最先想看到哪个数？拿它做什么决定？
- 这件事你只看，还是需要它代为催办或代办？

然后**先画一版**，请用户指着改：「这格不对」比「你想要什么」容易回答。出草图算一次判断，修改一次算一次。

定四件事：

1. **展示清单**，每条一句用户能读懂的话：这一格是什么 / 能立即得出什么结论 / 选择后去哪。详情、评论、流转、日志不在面板做。
2. **配置清单**：管什么 / 默认 / 候选从哪来 / 选错怎样 / 按项目记 / 何时生效 / 怎么清。
3. **分流**：反复做且要动平台的 → 交给 agent；多步、长等、中途要人、失败要续的 → 封成一个动作（按钮 + 交给 agent 的入口）；
   只是看 → 只读。
4. **状态矩阵**：每态「看到什么 / 能做什么 / agent 能接着做什么」。

产出：ASCII 画面（卡片、设置面、每种状态）+ 状态矩阵（左列图号）+ 图例。

判据：

- 用户对着图确认过每种状态，或指出哪格不对。
- 每格是用户可见或能操作的事，没有"系统内部会…"。
- 矩阵每个词都能在图例里指到屏幕；图例不能只是同义词。
- 每种缺失有一句可照做的话：缺什么、去哪补、谁补。
- 每个控件对应一句用户会对 agent 说的话，界面上有该句的位置。
- 真机上无法构造的状态也要有设计。

## agent 能力

**只问一句**：哪些操作会真正改动平台、必须先获得批准？批准时你要看到什么？

「用户会怎么描述这件事」「完成后需要知道什么」由 agent 自决，不问。

定五件事：

1. **能力清单**：每件事一句"agent 能做什么"；说明为何是独立的事，而不是某件事的选项。
2. **入参 / 返回**：贴上真实调用（参数 JSON）与真实返回正文（照抄），并补充默认值、上限（不要悄悄截断）、
   取值范围，以及参数错误时怎么改。
3. **全场景**：正常 / 没有 / 分不清是哪一份（不许猜）/ 参数错 / 超上限 / 能力未安装完成 / 要登录或超时 /
   还有下一批 / 截断（说清截了什么、多少）/ 没有当前项目。
4. **写操作两步**：先预览（说清将要做什么；画法见 [TOOLS.md](TOOLS.md) §5），再执行。预览让用户判断"要不要做"，不是"要不要允许"。
5. **批准范围**：改平台 / 改这台机器 / 改面板。批准时展示这次具体会发生什么（对象、版本、环境）；
   如果说不清，就先不要发起审批，停下来让 agent 去查。

产出：真实调用与返回，逐条贴出。能连上平台就真实执行一次；不能就用真实代码输出，并标注为样例。

判据：

- 每种情况有确定结果；拒绝文案带 agent 可执行的下一步。
- 入参与返回照抄；边界给真实报错原文。
- 分不清的那格不许猜、不许退回默认。
- 截断、越界、分页说清边界与下一批。
- 批准格写"会发生什么"，不写"这是什么操作"。
- 用户自行触发的入口无需审批，但与 agent 走同一条链路、得到同一结果。

## 联动

**只问一句**：agent 改完，多久看到、哪一格变？

其余（面板是否变化、运行几分钟时查看哪一格、交给 agent 后拿到什么）按 [LINKAGE.md](LINKAGE.md) 的口径自决，不问。

定五件事：

1. **何时变**：读这一格 → 该格按最窄切片重读，值与对话一致；读面板外的东西（明细 / 日志 / 子集）→ 不变；
   预览 → 不变；真实写入 → 该格显示新值；用户自行触发 → 立即变化。
2. **进行中**：显示到哪步；要登录给链接；失败给原因与原始输出。不画进度条、不画流程控制台。
3. **交给 agent 的内容**：哪一类、哪个对象、多少，加一句用哪个能力取明细。
4. **收起模块 = 该项目内 agent 也失去该能力**，开始时说明。
5. **不陈旧**：切换项目、其他窗口正在修改、程序刚刚更新，这三类情况要么实时反映，要么明确说明。

产出："变之前 / 变之后"两张 ASCII + 联动表（何时变、哪格变）。

判据：

- 用户对着两张图看过一次真实变化。
- 每格说清"何时变、哪格变、看到什么"；"哪一格"细到"某份数据 + 最窄参数"（`inventory/builds?env=dev`）。
- 面板不停在旧值；允许延迟但要说清。
- 每个"交给 agent"都说清 agent 收到的内容。
