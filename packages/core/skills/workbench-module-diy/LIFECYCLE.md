# 生命周期：从源码到用户看到

本页处理安装、识别、构建、生效、工具链与取消。正常安装、热换与发布做法看 [WIRING.md](WIRING.md)；面板内部原因先看 [SYMPTOM.md](SYMPTOM.md)。

## 装完没出现

- **症状**：「安装成功了，面板上怎么没有」。
- **判断**：`workbench_diy_status` 分开看是否已安装、已识别、当前项目已显示与产物齐全。
- **动作**：未安装就安装；已安装未显示就调用 `workbench_diy_show`；未识别转下一条；已显示但页面旧转「页面是旧版」。
- **谁动手**：agent 完成安装与显示；只有工具返回明确要求用户操作时才交给用户。
- **怎么说**：说清当前缺的是安装、识别还是显示，以及正在做哪一步；「安装完成」只描述安装，不能代替后两者。

## 已装未识别

- **症状**：「包已经在了，但工作台不认识这个模块」。
- **判断**：看 `workbench_diy_status` 的启动状态、初始化错误与声明被拒原因。
- **动作**：按原因修清单、声明或源码并重新构建；仍不识别时看是否属于必须重启的装载变化。
- **谁动手**：agent 修模块；必须重启时用户退出并重开工作台。
- **怎么说**：说「模块已安装，但启动检查未通过，正在修正」；需要重启时并入「无法热换」那一次说明。

## 源新于产物

- **症状**：「源码明明改了，运行的还是旧逻辑」。
- **判断**：`workbench_diy_status` 显示源码新于产物，或构建时间早于本次修改。
- **动作**：在模块工作区运行现有构建；持续修改可用既有监听构建，构建失败回 [REVIEW.md](REVIEW.md) 修。
- **谁动手**：agent。
- **怎么说**：「源码已更新，正在构建；构建通过后还要确认它已经生效。」

## client 改了要刷新

- **症状**：「宿主逻辑已经更新，卡片外观或浏览器交互还是旧的」。
- **判断**：本次改的是浏览器面，构建产物已更新且宿主已应用；纯宿主热换不要求刷新。
- **动作**：构建后刷新当前页面；样式变更也按构建与刷新结果核对。
- **谁动手**：agent 能经只读页面线确认就先确认；需要用户刷新时由用户操作。
- **怎么说**：「浏览器面已更新，刷新当前页面后生效。」只说一次，不提供无效按钮。

## 构建成功但没生效

- **症状**：「构建通过了，但模块行为没有变化」。
- **判断**：看 `workbench_diy_status` 的应用状态与构建推送；根外模块还要确认是否使用工作台自带的模块工具链。
- **动作**：缺推送就换用工作台自带工具链重新构建；等待应用就继续看状态；待重启转「无法热换」。
- **谁动手**：agent。
- **怎么说**：「构建已通过，但更新还没有进入运行中的模块，正在确认应用状态。」不能说「已生效」。

## 无法热换

- **症状**：「这次更新必须重启才能生效」。
- **判断**：`workbench_diy_status` 的 `applied.state` 为 `pending` 或 `unavailable`，并给出宿主自身加载、未纳管插件、安装声明变化或当前环境无法热换等原因。
- **动作**：先完成构建，再让用户退出并重开工作台；重开后核对识别与应用状态。
- **谁动手**：agent 完成构建与核对，用户重开工作台。
- **怎么说**：「需要退出工作台再打开一次。」说完等待，不重复提醒，也不给点了无用的按钮。

## 启动失败

- **症状**：「模块初始化失败 / 声明被拒绝 / 构建后无法加载」。
- **判断**：读 `workbench_diy_status` 的启动状态与原始原因；需要构建细节时看模块检查，不让用户转述堆栈。
- **动作**：按 [REVIEW.md](REVIEW.md) 修对应检查项（判据）或声明，再构建并重新核对；环境问题按工具返回给用户一个具体动作。
- **谁动手**：模块问题由 agent；只有外部账号、服务或权限问题才由用户处理。
- **怎么说**：先说「模块启动检查未通过，正在修复」；两轮仍未通过再说明哪项未通过与下一步，不贴报错原文。

## 无屏调试

- **症状**：「Desktop 没有可绑定的调试页 / 本机不能占用屏幕」。
- **判断**：确认页面调试能力是否可用；Desktop 的页面族只走带站点地址的只读线，调试与日志族不可用。
- **动作**：用 `workbench_diy_panel`、`workbench_diy_status`、直接路由与只读页面查询取证；仍无法确认的列入未验证。
- **谁动手**：agent；不要求用户截图或自行抓日志。
- **怎么说**：「本机没有页面调试能力，我会用只读结果核对；无法确认的项会标为未验证。」

## 工具链版本落后

- **症状**：「模块工具链与工作台不是同一代 / 根外模块没有推送构建」。
- **判断**：看 `workbench_diy_status` 的工具链状态与同步结果，确认当前调用的是工作台自带的 `dsh-wb-module`。
- **动作**：等待启动时的后台同步完成；使用工作区共享的工作台工具链重新构建，不在模块里另装一代。
- **谁动手**：agent。
- **怎么说**：「正在同步模块工具链，完成后会重新构建并确认生效。」同步失败才说明具体缺口。

## 工具包没开

- **症状**：「这一步需要的工具不存在 / 返回说工具包未开启或被收起」。
- **判断**：读返回中的当前流程步、需要的工具包与是否被用户手动收起；不要改用其他工具重试。
- **动作**：流程自动开的包等进入对应节点；录制与调试手动开 `diy-record` / `diy-debug`；用户手动收起且确实需要时，先说明用途再开。
- **谁动手**：agent；涉及用户明确收起的选择时先取得用户同意。
- **怎么说**：常规自动开包不打断；必须请用户决定时只说「下一步需要 <工具包> 来 <具体动作>，现在可以打开吗」。

## 审批被拒

- **症状**：「用户拒绝了 / 工具没有执行 / 审批前检查未通过」。
- **判断**：区分用户明确拒绝与材料不齐；读返回缺的是哪一项，已经发生的动作与未发生的动作分开。
- **动作**：材料不齐就补齐后重新调用；用户拒绝就停止该动作，不自动重试；需要替代方案时先给不改变外部状态的那条。
- **谁动手**：agent 补材料，用户决定是否批准。
- **怎么说**：「这一步未获批准，尚未执行。」有替代时补一句现在能做什么；不施压、不反复询问。

## 中途取消

- **症状**：「先停一下 / 不做了 / 取消这场流程、长任务或录制」。
- **判断**：确认当前是工坊流程、模块长任务还是录制，以及是否已经有外部写入。
- **动作**：工坊流程用 `workbench_diy_step` 的取消与原因；长任务用现有停止工具并遵守审批；录制先保住需要的材料再停止并清理。已发生的外部写入如实记录，不假装撤销。
- **谁动手**：agent 执行与清理；停止需要审批的长任务时由用户决定。
- **怎么说**：「已停止，后续步骤不会继续。」若已有外部变化，再补一句已经发生到哪一步、如何撤销或继续。
