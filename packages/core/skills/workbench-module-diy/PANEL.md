# 面板：内容、配置、状态、样式

步骤 1 的参考。

## 1 只放四类东西

| 类 | 例 | 承接 |
|---|---|---|
| 导航 | 换项目、切面板、折叠 | 界面自身 |
| 呈现 | 状态、数字、最近几条 | 轻交互（筛选、展开、复制） |
| 动作 | 单步发布、同步、提交 | 动作路由：用户按，记一次 run（ADR-0090） |
| 交代 | "交给 agent"、预填指令 | 转给 agent |

不放：批量、跨对象的平台写 → agent；详情 / 评论 / 日志 / 翻页 → "去平台看"。
单步动作可以有一个按钮，但必须与一把 agent 工具共用同一实现，并记一次 run；不能只在 UI 里另写业务逻辑。

## 2 封动作还是交 agent

单步、用户自己就能确认、且与一把工具 1:1 → 封动作（动作路由）。
批量、跨对象、需要用户逐步判断或编排 → 交给 agent。
长等、中途要人、失败要续，不改变归属：用户发起的仍是动作路由，agent 发起的仍是工具与审批。

## 3 什么算配置

只有用户在本面板的偏好：看哪份、显示哪些、钉哪个环境、绑定哪个对象。碰平台的不算配置。
形态：一屏选完 + 保存前校验；不做分页向导、多步流程。

## 4 展示清单

每行三项：

| 项 | 标准 |
|---|---|
| 这一格是什么 | 用户会说的话；有平台术语就重写 |
| 一眼得出什么结论 | 能支撑决定；不能就不放 |
| 点一下去哪 | 去平台或交给 agent，至少一个 |

同列卡片结构一致（标题、刷新、设置、"去平台"位置）。每个数字都要有 agent 能力能取到；每个按钮都要有等价的一句话。

## 5 配置清单

每项七栏：管什么 / 默认 / 候选（只列现存） / 选错（拒绝并列出仍可选项，不静默替换） /
记录范围（按项目，换项目不串；换仓库或对象时作废旧选择并要求重选） / 生效（保存后生效，成功回看板刷新，失败留在原地说原因） /
清除（用户显式清；收起或卸载面板不删）。

### 5.1 persistence：`view` 还是 `prefs`

| 写法 | 场景 | 刷新后 | 实现 |
|---|---|---|---|
| `view` | 卡片底部一次性选择（口径、天数） | 回默认 | 作 route 参数传给只读口；非法值写进 `wrongChoice` |
| `prefs` | 配一次长期有效（环境、忽略项、超时） | 保留 | `mount` 返回 `prefs: { resource, handle }`，`handle` 用 `deps.store` 落盘 |

宿主侧：

```ts
// mount(deps) 内；按项目分文件
const store = deps.store.for(UNIT_ID, workspace);
return {
  prefs: {
    resource: 'your-module',
    handle: (payload) => applyPref(store, payload),   // 校验 + 落盘 + 返回整份新偏好
  },
};
```

浏览器侧：写走 `prefs`，读取仍走模块只读口。布局与内边距用外壳默认（`Field` / `TextField`），不必为可读性写 CSS。

```tsx
const write = useHostWrite({ channel: 'prefs', resource: 'your-module' });
write.send({ ignored, timeoutSeconds, workspace });   // 控件：Field + TextField / ChoiceGroup；容器 SettingsSection；保存 SaveBar
```

`handle` 规则：未设置 ≠ 空（首次进入"第一次选"）；清空 = 回默认并删文件；按工作区分文件；
未知值报错并列出候选；去重、保留用户顺序。
保存成功后卡片按新偏好显示（写偏好 bump 该单元的事实，[LINKAGE.md](LINKAGE.md) §8）；失败留在原地说原因。

## 6 界面规则

文案（主句 / 原文、通俗、zh / en）见 [COPY.md](COPY.md) §3。

- 有默认可读的数据就直接显示，不先弹设置；只有分不清时才摆选择。
- 候选 ≤3 个时平铺，不放进下拉。
- 历史、明细默认折叠，露出最近一条；只有一条时不给折叠控件。
- 状态点只有四义：在做 / 完成 / 出错 / 未运行。
- 外链一律 `Link`（`h(Link, { href }, 文案)`；`h` 从 `react` 引）：新窗口 + `rel` + 箭头，唯一形态，
  没有 `icon` 口子；文案里不自带箭头。手写 `<a>` / `h('a')` 会被 `style` 判据判红。
  例外仅三类非正文链接：图标链、按钮样式的链、整行链。放宽走 `ANCHOR_EXEMPT`，只减不加。
- 跳整张卡对应的系统 → 卡头 `CardHead.platformHref`；跳具体页面 / 记录 → `Link`；触发动作 → dsh `Button` 或阻断屏 `action`。
- 标签 + 输入框用 `Field` + `TextField`，不自写 CSS。
- 组件选型照 [KIT.md](KIT.md)。
- **字号与重点**：走刻度，不整卡同字号 —— 刻度以 `--dsw-font-*` 的定义为准，别背数字
  （`workbench_diy_components` `scope: 'tokens'`、`bucket=font` 现查）。
  最重点的数字用最大一档（`--dsw-font-xl-24`），旁注用最小一档；刻度外字面值需在模块 `README.md` 说明。
  成列数字加 `font-variant-numeric: tabular-nums`。
- 颜色与间距走令牌；名字现查不猜：`workbench_diy_components` 给 `scope: 'tokens'`（`bucket` 按族、`name` 连浅/深值）。
  写进 CSS 的令牌名由 `check --only style` 对着现读的清单验，拼错判红。自写 CSS 只写布局（flex / grid / gap / 对齐）。

## 7 状态矩阵

状态全集：没有绑定 / 未接入 / 分不清是哪一份 / 正在读 / 有数据 / 正在做 / 卡住（登录、权限、超时、能力未装） /
读到但空 / 数字是上一轮。

每格三列：看到什么（哪句话、哪个画面、哪颗点）/ 能做什么（去哪补、点哪、重试）/ agent 能接着做什么（可照做的一句）。

规则：每句可照做；平台没给的格不留占位；读不到就说读不到并给原因，不显示 0；有确定答案就不打扰。
真机造不出的状态也要在设计里画；`plugin.test.ts` 覆盖五态（`check --only cards` 用七种外壳侧输入各跑一遍，
只判"是否干净退化"，不判画的是哪一态）。

### 7.1 图例

矩阵左列写图号，图按图号排。至少这些屏：有数据 · 空态（图标 + 一句话，无按钮）· 阻断（整卡替换：图标 + 话 + 按钮）·
提示（数据照常，顶部一条）· 骨架 · 在转（列表在，卡头刷新转）· 行内记号（状态点 + 编号 + 元信息 + 行尾两颗）·
状态点各档（撞色两档在图下注明区分方式）· 可点筛选 · 仅某模式出现 · 审批弹窗（每行谁给的）。

图里用界面真实文案；不用符号代替画面（形状与位置才是识别点）；画不成的写词并定义。
真机造不出的照样画；实现时用真实输入走到（空目录、坏路径、未选择）。

## 9 kit 不够时

先查 kit（`check --only kit`）。确无且需要标准控件时，可引 dsh 客户端原语（清单：`check --only primitives`）：

- 只在浏览器侧引（`src/client.tsx`、`src/components/**`）。
- `dsh.client.external` 声明 `@deepseek-ai/dsh-client-ui-primitives`；`devDependencies` 用与外壳一致的精确版。
  改完 `pnpm install`。
- 宿主侧不引：`source` 判据红；宿主 import `src/components/**` 还会被 `arch` 的 S23 判红。

kit 优先：kit 跟随外壳主题与语言。
